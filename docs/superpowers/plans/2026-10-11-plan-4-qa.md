# Plan 4 — Knowledge Q&A with citations Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Members of an organization ask a question in Vietnamese and get an answer built only from that org's published meetings, with every claim cited back to the exact utterance; questions without support get "Không đủ thông tin trong các cuộc họp đã phát hành."

**Architecture:** Publishing enqueues an Arq `index` job that writes `search_text` + embedding for approved/edited items and 6-utterance transcript chunks. `POST /api/v1/qa` runs: LLM filter extraction → hybrid retrieval (pgvector cosine + `pg_trgm` word similarity per source, one SQL each, always org- and published-scoped) → RRF fusion (k = 60, keep 12) → supersession expansion → numbered contexts → LLM answer with structured `{answer, used_refs}` → post-check that drops unknown refs. Embeddings sit behind an `Embedder` protocol with a real `bge-m3` implementation and a deterministic hashing implementation for tests and light dev setups.

**Tech Stack:** pgvector (`pgvector` Python package, `vector(1024)`, HNSW), `pg_trgm` (GIN `gin_trgm_ops`, `word_similarity`), sentence-transformers `BAAI/bge-m3` (optional dependency group), existing Anthropic `LLMClient` structured outputs, FastAPI, Arq, Next.js frontend.

**Spec:** `docs/superpowers/specs/2026-10-10-meetmind-mvp-design.md` (v3) — §7.2 (`items.search_text/embedding/indexed_at`, `transcript_chunks`), §11 (Agent 6), §12.1 (`POST /qa`), §12.2 (`/qa` page), §13.1 (QA unit + isolation tests), §13.2 (QA eval metrics). Plans 1–3 built the AI core, backend and frontend; reuse their patterns (org-scoped repositories, services commit, `FakeLLM`, `tests.backend.*` helpers, Vietnamese UI copy).

## Global Constraints

- Every retrieval query filters `org_id = principal.org_id` **and** meeting `status = 'published'`. Org X must never see or cite org Y data (dedicated test in Task 5).
- Embedding dimension 1024 (`EMBEDDING_DIM`, default 1024); model `BAAI/bge-m3` (`EMBEDDING_MODEL`); provider setting `EMBEDDING_PROVIDER` = `local` (sentence-transformers) | `hash` (deterministic, no model download). Default `local`; tests always use `hash`.
- Index contents (spec §11.1): each `approved`/`edited` item gets `search_text = "<loại>: <nội dung>. Lý do: <rationale>. Phụ trách: <owner>"` (omit the "Lý do"/"Phụ trách" parts when empty; `<loại>` = the Vietnamese item-type label, e.g. "Quyết định"); transcript chunks = windows of 6 utterances with overlap 2, storing `start_ts`, `end_ts`, `first_utterance_id`, `speakers`, `text` (`"Tên: câu"` lines).
- Retrieval (spec §11.2): vector top 20 items + top 20 chunks by cosine; keyword top 20 items + top 20 chunks by `word_similarity(query, text)`; RRF `k = 60`; keep 12 contexts; contexts ordered by `meeting_date` ascending (oldest first, newest last) with the instruction that the newest meeting is the current state.
- Refusal text exactly: `Không đủ thông tin trong các cuộc họp đã phát hành.` with `citations = []`.
- `app/ai/` never imports `app.core`, `app.api`, `app.services`, `app.repositories`, `app.models`. Embedder/QA agent code lives in `app/ai/retrieval/` and `app/ai/agents/qa.py`; SQL lives in `app/repositories/`.
- Prompts are versioned files `app/ai/prompts/qa_filter/v1.md`, `app/ai/prompts/qa/v1.md` (Vietnamese), loaded with `load_prompt`.
- Models: `qa_filter` and `qa` use the default model (`claude-sonnet-5-5`) via `AISettings.model_for`.
- Tests never call a real LLM or download a model. Backend checks: `cd backend && REQUIRE_DB=1 uv run pytest` (Postgres via `docker compose up -d db`), `uv run ruff check app ../tests ../evals`, `uv run mypy`. Frontend checks: `cd frontend && npm run lint && npm run typecheck && npm test`.
- NEVER run `ruff format` or repo-wide formatters. Commits: conventional, **no `Co-Authored-By` trailer, no "Generated with" line**.

## Review Focus

1. A question that matches only a superseded option ("Mình chọn MongoDB à?") must surface the final decision that replaced it, marked as current. (Task 5 test.)
2. Retrieval with no published meetings, or with only another org's meetings, returns the refusal — not an LLM call over empty context. (Task 5 test.)
3. The LLM citing `[7]` when only 5 contexts exist, or returning no refs → those refs dropped; no valid ref left → refusal. (Task 4 test.)
4. Reopening an item removes it from search until re-published, and re-publishing indexes only the changed items. (Task 2 test.)
5. A failed index job (embedder error) leaves the meeting `published` with a readable job error, and re-publish after reopen retries indexing. (Task 2 test.)

## Rulings recorded while planning

- The pipeline never emits `superseded` items: a FINAL decision carries `supersedes: [option labels]`. Spec §11.2 step 3 ("follow `superseded_by`") is implemented as **supersession expansion**: for every retrieved context (item or chunk) whose text mentions (casefolded substring) an option label listed in some decision's `supersedes` within the same meeting, that decision is added to the contexts (if not already present) and marked `mới nhất`; the hit is marked `đã bị thay thế`.
- Publishing stays synchronous; it additionally creates an `index` job and enqueues it after commit. An index job failure never changes meeting status.
